# 真实模型 Workflow 失败恢复验证

记录日期：2026-10-03。用户授权使用本机保存的模型 API 配置，实际调用在 2026-10-02 深夜完成。测试只使用独立临时工作区中的合成音频，不操作用户正常音频工作区、已安装插件或生产配置。

## 场景与结果

预置一个待排查的旧 Workflow 文件：顺序运行两个 RNNoise Graph。第一份输入是 48 kHz 单声道，第二份是 44.1 kHz 双声道。要求模型先原样执行以复现错误，再依据真实工具反馈修订流程，只处理失败部分，保留已经成功的输出。

实际执行通过，耗时约 30 秒，10 次模型请求、22 次工具调用；没有修改生产运行逻辑、模型提示词或调用上限。当前生产上限仍为每轮 16 次模型请求、40 次工具调用。

1. 原 Workflow 第一张 Graph 成功生成 good.wav，第二张 Graph 返回实际 C++ `unsupported_audio_format`，Workflow 状态为 failed。
2. 模型查看节点目录和运行历史，额外运行一次仅针对失败输入的 Graph 探针：重采样、转单声道、测峰值，不重新生成第一份输出。
3. 模型写入并校验新的 Workflow 文件，为失败输入添加 `audio_resample`（48000 Hz）和 `audio_downmix_mono`，保留 RNNoise 和 WAV 输出。
4. 修订文件实际执行成功，关联子 Graph 成功。两份结果导出到临时用户工作区 recovery-delivery 子目录，均为有效的 48 kHz 单声道 PCM16 WAV。
5. 第一份输入仅有一次处理记录，其输出与历史记录哈希以及交付文件哈希一致。两个原始输入逐字节保持不变；第二份交付文件哈希与修订 Workflow 的成功子 Graph 产物一致。

## 证据与范围

结论来自真实工具回执、执行时的 Workflow 内容指纹、RunStore 父子运行记录、结构化 C++ 错误和文件检查，不采用模型的文字总结作为通过依据。原始流程必须先失败，不能用预先修改绕过复现来冒充失败恢复覆盖；这是一项受控回归任务，不是要求普通用户任务故意失败。

本机审计产物位于 `out/live-workflow-recovery-20261002/`：report.json、预置及实际执行的 Workflow 副本、两份合成输出音频。该目录按任务开始日期命名，已被 Git 忽略。报告不包含 API 配置、密钥、模型原文或服务端原始响应。执行文件编号来自运行记录顺序，不表示时间先后。

通过的是一次有明确诊断目标的格式错误恢复。未据此验证所有故障类别、跨重启继续任务、长期无人值守、实时处理或听感质量。自动测试检查导出音频格式/哈希，并要求调用元数据工具；元数据工具的成功计数本身不用于证明每条响应都对应指定输出。
