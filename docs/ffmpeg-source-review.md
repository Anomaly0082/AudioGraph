# FFmpeg 源码与许可证材料核对（2026-10-25）

本报告记录旧 BtbN 全量二进制的来源核对。随后已改为[音频精简自构建](ffmpeg-audio-build.md)，不再携带下述 rav1e 依赖；本报告的缺口结论不适用于新构建。若重跑旧材料收集脚本，需要用 `--runtime` 指定保留的匹配全量运行库备份，不能混用新版运行报告。

已完成现有材料的清点、对应关系记录和许可证原文归档。**正式分发仍未放行**：当前第三方构建存在未保存的构建时依赖输入，具体见下文。没有修改运行二进制、分发门禁或应用功能。

## 下载这个大包的用途

许可证文字本身很小。大包用于保存对应当前二进制的第三方源码、子模块、内嵌依赖和源码中的作者/许可声明；另有精确版本的 FFmpeg 源码 ZIP、BtbN 构建脚本及补丁 ZIP。它不是程序运行时依赖，也无需随每次启动加载。

[FFmpeg 官方说明](https://ffmpeg.org/legal.html)强调源码与二进制对应，以及外部库各自的义务。收集源码与声明是分发准备的一部分，不等同于已经满足全部义务。这里涉及的构建报告 LGPL-3.0-or-later；不能只依据“FFmpeg 通常是 LGPL-2.1”替代实际构建结果。

## 固定版本和核对结果

- 二进制：BtbN `autobuild-2026-10-22-13-06`，`win64-lgpl-shared-8.1`。
- FFmpeg revision：`5c4f5744cd60943125a78db692b728210102f255`。
- 构建脚本 revision：`937868360a21d711ec94a33f5591d345ad9b7754`。
- 三个来源 ZIP 均按锁文件校验，副本再次校验；当前运行目录的 9 个 EXE/DLL 与来源记录逐个核对一致。
- 完整缓存实际包含 **129 个源码归档和 129 个符号链接别名**，不是 258 个独立依赖。
- [原始 win64 LGPL shared 8.1 作业](https://github.com/BtbN/FFmpeg-Builds/actions/runs/39776938430/job/119820947257) 的 BuildKit 日志记录 **89 个构建脚本步骤**，其中引用 **86 个不同的源码缓存归档**，全部在下载包中找到。
- 其余缓存来自其他目标/变体等，完整保留用于来源核查；不能因此断言当前二进制链接了它们。
- 归档 **1,294 条许可证、作者、版权、专利声明或含声明头文件记录**；按内容去重后 **695 份，4,378,756 字节（约 4.18 MiB）**。这些数量不是依赖数量，也不是适用于运行程序的独立许可证数量。
- 核对包含 NVIDIA 头文件内的声明，以及 GLib 内嵌 `proxy-libintl` 的许可文件。librsvg 自带 vendor 目录及声明，已收入；不能将它与缺 vendor 的 rav1e 混为一谈。
- AMF 下载脚本主动删除 `.git`，因此缺少 HEAD 元数据并不等于版本不匹配；其来源由固定下载步骤、原始缓存及内容 hash 记录。

缓存文件名中的长 hash 是上游**下载命令文本的 hash**。本次另算每个 tar.xz 的真实 SHA-256，分开记录，避免误把文件名当作内容校验值。

## 本地交付目录

`build/ffmpeg-source-materials-20261025-v3/`（整个目录被 Git 忽略）：

| 路径 | 内容 |
| --- | --- |
| `sources/` | 三个原始源码 ZIP，字节不变 |
| `NOTICE-INDEX.md` | 按组件查看原文的入口 |
| `licenses/` | 按内容 SHA-256 命名的原文；换行、编码、版权文字不改写 |
| `inventory/notices.json` | 每份原文对应的源码包、原始路径和内容 hash |
| `inventory/components.json` | 所有 129 个缓存包、版本引用、观察到的 Git HEAD、内嵌归档等 |
| `inventory/active-dependencies.json` | 实际构建作业引用的 86 个源码缓存及日志证据 |
| `inventory/cache.json` | 258 个条目的类型、别名目标及实际归档 hash |
| `recipes/` | 供阅读的依赖脚本副本；完整补丁、Dockerfile 等仍在来源 ZIP |
| `evidence/` | 原始构建日志与独立静态审查记录 |
| `review-summary.json` | 核对数量、当前缺口及 `redistribution_ready:false` |

该目录是**审查材料包**，不是已批准分发的安装包。原文索引包括未启用变体、测试代码及其许可，不能把全部文本简单拼成“当前程序的许可证列表”。附带的运行 provenance 是本次运行目录的原始快照，未因获得源码缓存而改写历史状态。

## 尚不能证明完整对应的部分

| 项目 | 证据与剩余工作 |
| --- | --- |
| rav1e 的 Rust 依赖 | `scripts.d/50-rav1e.sh` 下载时只 clone；构建时 `cargo update cc`、`cargo cinstall`。缓存有 rav1e 源码，却没有该构建解析后的完整 vendor。原始作业日志 4270–4271 行显示这一步为 `CACHED`，未记录历史解析结果。需要原始层的更新后 Cargo.lock 和对应 crates，或另行构建可完整追溯的新二进制。重新解析今天的依赖不能证明旧二进制的来源。 |
| 工具链/目标运行库的声明 | 已记录原始 win64 基础镜像 digest、ct-ng 配置及静态链接 GCC/C++ 运行库选项，但尚需确认实际目标运行库的许可/例外与声明覆盖。普通编译器、Docker、Ubuntu 等构建工具的源码不应一概视为应用必须分发的源码；此项重点是最终带入二进制的运行库。 |
| 正式发布配套 | 需确认适用的 notices、二进制与对应源码包的配对、发布下载位置与说明，再启用正式分发入口。当前脚本保持拒绝不完整分发。 |

这些缺口不影响本机开发。无需再盲目下载一个“更新的源码包”；它不能补证当前固定二进制。后续可选：取得原始构建层的准确材料，或者单独构建只含所需音频功能、版本固定且完整留存源码的新 FFmpeg，再做互转回归。后者会替换当前 FFmpeg 二进制，不属于本次材料整理。

## 可重复的离线收集

```powershell
python scripts/collect-ffmpeg-notices.py --output build/ffmpeg-source-materials-new
python scripts/test_collect_ffmpeg_notices.py
```

输出目录必须不存在。脚本核验三个固定 ZIP 后复制原包，只读取源码归档、输出 hash 命名的声明文件，不执行上游代码、不创建源树中的符号链接，也不会把 `redistribution_ready` 改为 true。原始作业日志及人工/独立对应关系审查是附加证据，不由纯离线收集脚本自动推断。

合成测试覆盖原文保留、去重、来源 hash、目录穿越、不覆盖已有目录、别名校验、Linux 冒号文件名、超限声明记录、NVIDIA 头文件及 GLib 嵌套声明。真实材料检查还逐个验证了原文内容 hash 和作业缓存引用覆盖。没有运行原生 UI 或任何归档内脚本。
