# 统一运行记录

“运行记录”统一展示手动 Graph、AI Graph 和 AI Workflow；Workflow 中的 Graph 作为子记录，可定位到对应步骤/循环迭代。记录由 Rust 执行入口捕获，不依赖前端页面是否打开或模型是否总结成功。仅校验配置不会创建执行记录。

## 保存什么

- 每次运行独立 ID、类型、来源、父记录、开始/结束时间、耗时和状态。
- 本次实际配置的副本。Workflow 保存固定的程序内容与本次输入覆盖；Graph 保存本次提交配置。
- 实际结果和错误；Workflow 保留步骤报告，Graph 保留后端结果。
- 文件引用：所属用户/AI工作区、相对路径、用途、大小及可取得的 SHA-256。输入在运行前记录，输出在结束后记录。不保存 API Key、模型配置或整段对话。

配置编辑不会修改历史记录；新运行创建新记录。终态不能被迟到回调覆盖。原本尚未结束的历史在应用重启后显示“已中断”，不猜测成功、不自动重跑。重启不意味着磁盘上尚未完成的输出被撤销。

记录存储在应用数据目录的 `run-records/v1/<项目标识>/records`，与用户音频目录及 AI 可写目录隔离；没有给模型开放删除/改写记录的工具。记录是本地审计与回看数据，不是防本机恶意程序篡改的安全日志。

## 文件引用不是备份

“检查文件状态”按保存的路径检查当前文件，再对照大小和哈希：

- 与记录一致：有有效的历史指纹，且当前内容一致。
- 文件不可用：原路径没有文件，包括被删除或改名。
- 文件已变化：原路径存在，但内容与已记录指纹不一致。
- 无法验证：未取得历史指纹、文件太大、读取受限、检查期间变化或触及检查预算等；不能视为内容一致。

检查不会修改历史指纹。音频不会被自动复制进记录目录；删除源文件/输出后，本次运行仍有配置和结果记录，但不能保证重新试听或复现。音频备份、改名后重新定位不在本轮范围内。

## 页面与兼容

主导航为处理工作台、Graph 编辑器、运行记录、设置。列表展示名称、状态、时间与来源，配置/执行详情使用“查看…”按钮展开。当前手动任务直接在匹配的运行记录行提供“停止”，不再单列“当前任务控制”面板。终态完整结果取得并保存后自动释放后台任务，不删除持久记录或音频；真实收尾失败时显示“重试收尾”，不会自动重跑处理。

结果读取、落盘和释放严格按顺序执行；没有待保存记录的任务不再次补取结果，释放后不再调用tasks.result，避免把“已释放所以查不到”误报成运行记录故障。状态未知时需先恢复连接，不能将未知任务直接当成已完成释放。

## 手动验收

1. 打开测试工作区，手动执行一个输入→Gain→输出 Graph；在运行记录中查看结果及配置。编辑草稿后回看，历史配置不变。
2. 在 Workflow 模式让 AI 创建并运行三组增益程序；列表应出现一个 Workflow，展开可见三个子 Graph，每个有独立配置与结果。
3. 关闭并重开程序，重新打开同一工作区：完成记录仍可查看，不自动再次执行。
4. 在测试文件上检查文件状态，再修改内容、改名或删除：再次检查应分别提示已变化/不可用；原始运行状态不被改成失败。
5. 中途停止运行：查看实际取消/失败状态与已有输出。确认界面没有旧实验入口，原始音频与新运行记录不受旧实验清理影响。

自动测试不替代真实窗口及模型服务的手动验收。单条记录与历史扫描均有容量限制，超限或损坏明确提示，不把未读取的数据冒充完整历史。

当前限额：配置4MiB、结果详情512KiB、整条记录6MiB；结果过大时保留真实终态，并明确标注详情未保存。文件哈希每文件最多256MiB、每批512MiB及5秒软预算，超限保留引用但不声称已验证。列表最多500条，扫描有32MiB/2秒/10000项软预算；扫描不完整时显示警告，历史文件不会被删除。

## AI查询与反馈调整

外层AI可在Graph和Workflow模式下使用三个只读工具：

- `runs_list`：按kind、state或parent_id筛选摘要；parent_id为null时只看根记录。默认10条、最多20条，用返回的cursor继续。history_incomplete表示底层扫描不完整，不能据空列表断言“没有历史”。
- `runs_read`：按id读取summary、configuration、result、files或error。可用相对所选section的JSON Pointer精确选择配置/结果/文件字段。小值完整返回，大对象返回子项目录，大文本返回明确标注的片段。目录可分页（默认20项、最多40项），文本按Unicode字符分页（默认及最多2048字符）。`complete=false`的目录和片段不是完整Graph，需继续读取，不得用缺字段的预览直接运行。
- `runs_check_files`：按id检查当下文件状态，并分页返回；默认20项、最多40项。检查不改变保存的指纹，也不是音频备份。文件状态可能在检查后变化。

查询按当前项目隔离，不接受自由磁盘目录，也不提供历史编辑/删除或“覆盖重跑”。Graph模式只可据历史准备新配置，仍需用户手动执行；Workflow模式可以调用现有执行工具产生新记录。新执行结果提供run_id，旧配置、旧结果和原音频不被反馈调整过程覆盖。AI应先确认旧文件仍存在，再复制输入或改为当前AI空间路径，并选择新的输出文件名。

查询到的历史配置、结果、文件路径和指纹会进入当前模型API的请求；不会上传音频文件。此数据用途已由用户明确允许。提示词将历史视作数据而不是指令，不把保存的成功状态等同于当前文件仍可用，不声称听过音频。单条工具响应有24KiB以内的硬限制，若累计查询触及整轮128KiB上限仍会明确停止；没有后台无限搜索或自动续跑。

推荐手动验收：在Workflow模式发送“查看这个项目最近成功的增益处理记录；我觉得音量偏小，在原配置基础上提高3 dB（仍需满足节点范围），保留原结果，用新文件名运行，并对比两次实际指标”。确认AI先查记录/文件，产生独立新运行；重开软件的新会话也能查到持久记录。判断音质仍依赖实际指标或用户反馈，不以假模型测试代替真实服务质量。

本次历史工具接入验证：前端89项、Rust105项通过，付费API实测1项保持忽略；独立审查完成。包含跨项目拒绝、只读快照不变、大字段按需读取与分页边界，以及全新会话本机假模型收到真实历史并写出调整配置、真实C++按新参数生成独立结果。未调用用户真实模型API或操作真实窗口。
