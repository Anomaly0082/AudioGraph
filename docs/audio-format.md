# 音频信息与离线格式适配（P10）

这一阶段解决「输入WAV不是48 kHz单声道，RNNoise节点拒绝执行」的问题。
不改变Graph/Executor分工：文件信息由受控查询获得，转换由图中明确可见的节点完成。

## 新接口与节点

| 名称 | 作用 | 当前边界 |
| --- | --- | --- |
| `audio.inspect`（MCP为`audio_inspect`） | 查询路径、采样率、声道、帧数、时长及编码 | 工作区内现存普通PCM16 WAV；只读，不创建任务 |
| `audio_downmix_mono` | 单声道原样通过；双声道按`(L+R)/2`混合 | 8–192 kHz，1或2声道；不猜测多声道布局 |
| `audio_resample` | 按整数参数`sample_rate`重采样 | 输入/目标8–192 kHz，保留单/双声道；仅整段离线 |

查询读取文件头，不扫描完整音频采样，不检测响度/峰值/噪声质量，不上传音频。最多检查1024个RIFF块，过多时明确拒绝。文件在查询后仍可能被外部修改，查询不是锁定文件的保证。坏文件、不支持的编码、目录、缺失文件或越界路径明确报错。

两个转换节点复用现有Audio类型，输入只读；每次执行独立状态，支持协作取消。同采样率/已经单声道时原样共享只读输入。PCM16以外的WAV、MP3/FLAC、更多声道、实时格式转换仍未实现。

## 图如何组织

典型44.1 kHz双声道输入：

```text
wav_input → audio_downmix_mono → audio_resample(48000) → rnnoise_denoise → wav_output
```

`examples/graphs/denoise.json`和桌面降噪模板已使用此结构。输入已经48 kHz单声道时，两转换节点等同旁路；降噪节点本身仍保持严格格式约束，不在其内部隐藏转换。

## 内置AI与外接MCP

内置助手新增「输入 WAV 路径（可选）」字段。处理音频时明确填写它（如`input13_cut.wav`）：Rust先调用`audio.inspect`，成功后把元数据和已注册节点描述提供给模型。检查失败时不发送模型请求。空路径保留纯文本/手写需求的原流程，但此时没有真实音频元数据，不能保证模型推断正确。

不从自然语言猜路径，也不让AI扫描目录。一次提案＋一次结果解释的HTTP上限不变。模型建议仍要由用户检查文件路径、节点和参数后确认，才执行。路径字段是编排上下文，不是替代workspace与人工确认的权限边界。

外接MCP客户端可以先调用`audio_inspect({path:"input.wav"})`，再利用节点描述构造Graph。内置助手的模型仍只有`propose_audio_graph`提案工具，音频预检由宿主在请求前完成；没有增加自由工具循环。

## 算法与时序限制

重采样复用已固定miniaudio 0.11.23的线性插值＋四阶低通，不是高保真sinc算法。输出帧数为`ceil(输入帧数 × 目标采样率 / 输入采样率)`，与原时长相差小于一个目标采样周期。

丢弃库报告的整数启动延迟，且异率转换至少丢一帧，输入结束后补零排空到规定长度。最少一帧的策略避免极端降采样只返回初始化零样本，可能额外偏移至多一个目标采样；不会完全消除IIR频率相关群延迟。极短文件/首尾可能衰减，不能把转换当作无损往返。

双声道反相信号平均后可能相消，这是所选混合规则，不做响度归一化。转换要求有限采样，不主动限幅，滤波过冲可能超过`[-1,1]`；若后接RNNoise因此拒绝，可显式加前置Gain降低幅度。降噪后增加+12 dB也可能在PCM16输出时削波，应检查`clipped_samples`并试听。
