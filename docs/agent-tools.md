# 最小工具层与双工作区

## 已确认边界

Graph模式只提供查询、配置编辑和校验工具，模型没有执行工具；手动运行仍由现有Graph编辑器发起。Workflow模式允许模型直接调用受限工具（包括运行已有Graph），不逐次弹执行批准。另提供确定性的[Workflow JSON文件运行器](workflow-v1.md)：程序内部没有模型调用或人工等待，执行完毕返回报告，由外层AI继续判断。不能将模型的多轮工具调用当作Workflow程序本身。

用户工作区可以读取、创建新产物，AI不能覆盖、修改或删除其中任何已有文件。AI工作区由程序在应用数据目录按用户工作区隔离创建，可在其中增删改文件；两个物理目录不能重叠。导入是独立复制，导出只能新建。AI没有Python、Shell、任意网络、设备/实时音频或动态插件工具。

目录能力：`directory_create({path:"project/round/outputs"})`只创建AI空间目录（可补齐父目录），根目录不计，最多3层；已有正常目录返回`created:false`。根、越界、链接及文件占位拒绝。相同深度限制适用于`file_write_text`与`file_copy_to_ai`的目标父目录，超限在创建任何目录前拒绝。该工具在Graph/Workflow模式和Workflow文件call中均可使用，不赋予用户空间任意mkdir权限。

导出分组：`file_export({path:"project/round/outputs/result.wav",user_path:"batch-001/result.wav"})`可自动创建用户工作区下一级`batch-001`，同批其他文件继续导出到该目录。默认提示AI选择一个新批次目录，仅交付需要的成果，不把探针和中间文件全部导出。既有正常目录可以追加新文件，但已有同名文件绝不覆盖。不会自动创建缺失的多级用户目录，不提供递归目录导出；用户明确指定根目录文件时保持兼容。创建目录前检查源文件，失败可能保留空目录或先前已成功导出的文件，不承诺整批回滚。

目录增量验证：Rust全套110项通过，付费API实测1项忽略；覆盖中文目录、多文件同目录导出、同名保护、有效源下的链接拒绝、三级目录与幂等创建、超深write/copy无目录残留，以及Workflow导出相对路径和运行记录指纹。未操作用户实际目录或调用真实模型服务。

## 文件与执行路径

第三方节点由本机启动插件快照加入宿主节点目录；手动与AI后台共享同一快照，AI没有安装/更新DLL或选择任意插件路径的工具。元数据包含非敏感插件来源、实际能力和版本，运行记录的node_plugins保留所用节点来源。外部整段节点支持Audio/Text/Number和普通标量参数，音频文件读写由内置节点组合；新版宿主另支持手动实时图中的ag.realtime_audio/1处理器。AI的nodes_list仍过滤实时域，graph_run/graph_validate仍只允许offline/streaming，不因此允许开设备。插件FilePath、普通离线streaming及异步声明仍拒绝。整个宿主目录暂限32KiB，超限包有诊断，不静默截掉配置字段。原生插件是用户信任的本机代码，可能自行联网处理音频；内置文件工具的权限限制不能被解释为插件代码沙箱。

`workspace_list`支持`offset`（默认0，最大10000）与`limit`（默认100，最大200），按文件名稳定排序，跟随`next_offset`读取后续页。单页条目内容还受16KiB预算限制，可能少于limit；`page_byte_limited`说明字节截页。单次扫描最多10000项或2秒，触限标记`partial:true`、`total:null`，只代表已扫描子集，不能声称全目录已遍历。目录变化时不同请求不保证同一快照；不提供递归遍历。

工具参数使用`space: user | ai`与相对路径，不接受磁盘绝对路径、父路径、设备路径、符号链接、junction或硬链接绕过。Graph校验明确指定空间：Graph助手一般为用户空间编辑配置并用`space=user`校验，用户载入编辑器后手动运行。模型调用`graph_run`则仅在AI工作区，文件输入先通过复制工具导入，输出保留在AI空间，需要交付时显式调用导出工具。运行使用现有control-cli独立实例，不改变用户手动运行的会话或C++ Node/Executor契约。

统一工具表：`workspace_list`、`directory_create`（仅AI空间）、`file_read_text`、`file_write_text`（仅AI空间）、`file_delete`（仅AI空间）、`file_copy_to_ai`、`file_export`（AI到用户，仅新建）、`audio_inspect`、`nodes_list`、`graph_validate`，以及仅Workflow模式可用的`audio_convert`、`graph_run`、`workflow_validate`、`workflow_run`。Workflow文件可调用`audio_convert`及其他基础工具，不能递归调用Workflow工具。

`audio_convert({source_space:"user",source_path:"input.m4a",path:"converted.wav",output_format:"wav"})`将普通本地音频转为AI空间中的新文件。`output_format`可选`wav`（默认PCM16）、`flac`、`mp3`、`m4a`，扩展名必须匹配；MP3/M4A为有损编码。无需先复制源文件；不改源、不覆盖目标，目标父目录须已存在，AI目录深度不超过3层。默认保留采样率和单/双声道，编码器不支持时失败；可显式指定整数`sample_rate`及`channels:1|2`，不会静默混音或重采样。返回`space/path/output_format/encoding/sample_rate/channels/frames/duration_seconds/bytes`等元数据，压缩输出`frames:null`而非估计PCM帧数。现有Graph和`audio_inspect`仍需PCM16 WAV，其他格式用于交付，交付仍用`file_export`。输入512 MiB、输出256 MiB、AI总配额512 MiB和120秒/Workflow剩余期限限制不变。取消和失败不发布半成品。详见[文件格式转换](audio-format.md#文件格式转换界面与内置ai共用)。

Workflow另提供纯数据步骤`compute`（add/sub/mul/div/abs）、`concat`（0..64个字符串/数字拼接）、`filter`（按条件保留完整项）和`select`（按有限数值取最小/最大项，保留参数与文件路径）。筛选输入最多16项，空选择found=false，并列取首项；条件/by中的item/index为临时作用域，不泄漏到外层。它们不是新的外层AI工具，不扩大文件/设备权限；AI通过编写Workflow文件使用，并以`/steps/id`读取结果。系统提示和workflow_validate说明提供准确格式、数值/类型/容量限制及先检查found再导出的规则，具体规则与示例见[Workflow v1](workflow-v1.md)。不支持把字符串当作算术、模板或Python执行，也不自动评价听感或运行无限搜索。

外层AI另提供`runs_list`、`runs_read`、`runs_check_files`三个只读历史工具，两种模式均可用；不增加Graph模式的执行权限，也不加入Workflow v1内部call白名单。历史查询仅访问当前项目的运行库，不能传入任意磁盘目录或其他项目标识。工具会把按需查询的历史配置、结果、文件路径与指纹送到当前配置的模型API；不读取并上传音频内容，不包含模型API配置。用户已明确同意此数据用途。

查询应先取摘要，再按记录ID获取相关section/JSON Pointer；大对象返回子项目录，大文本返回片段，不把预览作为完整Graph。扫描不完整、记录详情被省略或文件无法验证时必须保留提示。每个历史工具数据返回硬限24KiB以内（并预留工具封装余量），整轮模型请求仍受128KiB限制。新Graph/Workflow执行返回`run_id`方便回查；Graph执行失败的错误信息也会附已创建的记录ID。记录查询不新建执行记录，也不修改旧配置、音频或记录终态。

文本工具返回内容会进入模型上下文；音频检查只返回元数据，不上传音频样本。API Key与认证头不进入记录。读取文件产生的文字视作数据，不授予新的工具权限。

## 最小调用循环

每次用户发送一条消息，模型可提出工具调用；宿主逐个检查并执行，把结构化成功/错误结果送回模型，再继续下一步。工具失败不是成功，但模型可以根据错误调整后续调用。模式在服务端固定于本轮请求，隐藏工具以外仍必须在分派器中拒绝越权调用。

每轮用户消息最多16次模型请求、40次工具调用（原8/20已提高），模型单次请求超时沿用现有45秒限制；文本读写64KiB，文件复制256MiB，AI文件工具配额512MiB。Graph工具有执行时限、取消和子进程清理，不承诺OS级沙箱或恶意节点隔离。达到上限停止并说明，不能偷偷开下一轮绕过预算。Workflow文件内部的步骤/工具预算不随此调整。

`graph_run` 可选 `timeout_ms`，默认 300000（5 分钟），允许 1000–1800000 的整数；`graph_validate` 不接受此参数。Workflow 中仍取 Graph 预算与外层剩余时间的较小值，因此不能靠嵌套延长总期限。预算包含准备、校验和运行等待；轮询到期会请求取消并等待后台清理，非操作系统级硬截止。运行配置记录请求预算、实际有效预算和是否受 Workflow 截止约束。

每次模型请求携带剩余调用预算，临近上限要求收尾；错误回执提醒针对已有错误修正，不反复读取完整结果、探查无关文件或擅自改变处理顺序。同名工具、相同参数失败两次后，在没有成功变更环境的操作时拦截第三次调用并停止本轮。成功写文件、转换或执行会解除旧失败计数；失败 Workflow 中已经成功的变更步骤也算实际变更。这不是结果缓存，也不会自动重试工具。

调用次数或上下文触限、重复失败停止时，不再额外请求模型：程序从本轮真实工具回执汇总 Graph/Workflow 成功与失败次数、已写文本/配置、返回的输出路径、成功导出及最后错误，标明未执行的待调用项。保存配置不代表执行，测试成功不代表用户目标完成；文件路径是执行时的记录，不承诺文件之后未被修改或删除。原始调用详情和运行记录保留。模型对提示的遵循仍有不确定性，防重复检查也不能识别所有语义相同但参数不同的排查。

停止请求要中断等待中的模型请求，并阻止后续工具调用；已开始的Graph协作取消并清理进程后才释放本轮。文件操作可能已完成，取消不能声称回滚。窗口关闭同样等待工具清理，不能留下后台子进程。

## 本轮界面范围

在现有工作台使用通用工具助手，展示Graph/Workflow模式、双空间位置、对话和工具输入/输出，复用已有模型设置。旧“单次Graph提案”和参数实验入口及挂载控制器已移除，旧底层接口保留作回归；保留快捷模板。主导航为工作台、编辑器、运行记录和设置；编辑器内区分Graph与Workflow，AI生成的完整配置可只载入草稿，由用户校验并手动运行。历史工具复用现有调用详情，不另建专用AI表单。详细信息统一用“查看/收起”按钮，不使用原生三角折叠项。

AI会话已按工作区持久化：支持新建、选择和继续，打开工作区默认载入最近更新的会话。每个会话固定Graph/Workflow模式；切换模式会选该模式最近会话，或准备新会话，不修改旧会话权限。只读载入不会请求模型或执行工具。完整后台长程任务与Workflow内部检查点恢复仍未实现。

模型续聊使用所选会话最近3轮的可见需求、回复、附带配置及工具回执摘要；大字段明确标为省略，旧结果通过runs工具按需查询。请求接近128KiB时按整轮移除更早上下文，不删除磁盘历史。恢复的历史包装为数据，不重放tool_calls，也不把旧工具意图当作本轮执行命令。供应商需要的`reasoning_content`只用于同轮内存续接，不保存到会话文件。本轮需求与配置、模型可见回复、工具输入/结果仍可展开，但不冒充完整请求抓包。

会话存储位于应用数据目录、独立于用户和AI可写文件空间，按canonical工作区标识隔离。每轮先保存用户需求，再在工具调用前保存意图、完成后保存回执和关联run_id。若存储失败，停止后续调用并说明已有副作用可能保留。上次退出时未完成的轮次显示“已中断”，不会自动重试；只能由用户发送新消息继续。新建会话不清空旧记录，未发送输入框草稿只在当前应用内保留。

容量边界：每会话最多100轮、8MiB（新轮预留安全余量），超限要求新建会话而不是默删用户原文。界面每次读取最近20轮，可查看更早消息；过大的工具详情和回复保存时会附明确省略标记，并保留关联运行ID。模型API地址/Key配置、认证头及供应商推理字段不会写入会话DTO；用户主动写在消息中的内容仍属于对话正文。查询到的历史在主动发送新消息后按需进入当前模型API请求，单纯打开会话不联网。

开发验证使用本地假模型和临时测试数据，不调用用户付费API。手动验收：发送一轮→新建会话并切回→重开软件、打开原工作区→继续提问，确认能引用上次需求与结果；中断工具调用后重开应看到中断提示，不自动产生新文件。关联运行记录按钮应打开对应记录而不是发起执行。

2026-10-01会话增量验证：前端111项、Rust132项通过，付费实测1项忽略；独立审查完成。覆盖新进程/新manager续聊、无推理与Key配置落盘、项目/模式/会话隔离、重复请求拒绝、待执行工具不重放、保存意图失败零副作用、容量满保留用户原文，以及前端迟到响应和旧磁盘检查点不覆盖即时回执。真实窗口和供应商续聊质量仍需用户验收。

512MiB是文件工具的配额约束。Graph执行中会轮询检查并在超额后停止，也会在结束后检查；这不是磁盘硬配额，不能保证节点写入从不暂时超过阈值。失败/取消可能保留已创建产物，不自动清理用户或AI空间的已有文件。

## 手动验证

1. 打开一个小型测试工作区，进入工作台的“AI助手 / 工具助手”。模型设置复用原有保存值；先展开工作区信息，确认用户目录和AI目录分开。
2. 选择Graph模式，取消不必要的“附带当前Graph草稿”，发送“在你的工作区创建 hello.txt，写入hello，再读取它”。应看到写入、读取及工具返回，用户目录没有变化。
3. 请求把hello.txt交付为用户工作区的新文件；再次交付到同名文件应失败，原字节不变。AI可修改/删除自身hello.txt，但不能修改用户已交付文件。
4. Graph模式请求运行Graph，应被拒绝或解释模式不支持。可让AI根据节点目录编辑Graph JSON；成功写出的Graph可以明确载入现有编辑器，需用户手动运行。
5. Workflow模式发送“把用户目录的input.wav复制到你的空间，运行一个增益Graph，再交付为一个新的输出文件”。无需逐次确认；展开工具参数/结果，确认Graph处理在AI空间，交付只创建新用户文件。
6. 调用期间点停止；不应再发起后续工具。已完成的文件写入可能保留，不能把停止理解为撤销。Graph工具的进程清理完成后本轮才结束。
7. 将`examples/workflows/`中的示例复制到用户测试工作区。让Workflow助手先校验`gain-comparison.workflow.json`：不得生成音频；再运行，按需覆盖`inputs.source`为实际PCM16 WAV文件名。应返回三次增益处理的结果，原音频不变。重跑须更换导入和输出文件名；同名文件不能被覆盖。`condition.workflow.json`可单独验证条件与变量，不产生文件。

此处调用用户配置的供应商会产生正常API费用；开发只跑本地模拟请求和临时目录中的真实C++任务。图执行/文件权限是可信内置工具的约束，不是对恶意本机程序或恶意C++插件的隔离。
