# 最小参数对比实验

## 范围与验收

实验层复用现有Graph、任务接口和Executor，不增加通用Workflow，也不训练神经网络。首版仅整段离线Graph，恰好一个wav_input、一个wav_output，无其他文件路径参数；最多4个可调数值参数，每批2～4个候选。边界必须在节点Schema范围内，整数规则仍有效。Graph拓扑与其余参数在实验中固定。

1. 从编辑器草稿创建实验，填写目标与可调参数范围；先校验Graph和参数定义，再把输入复制到工作区内的`.audio-experiments/<id>/input.wav`作为固定样本。只有用户明确创建实验才复制文件。
2. AI工具`propose_parameter_candidates`只接受候选标签和按固定参数顺序排列的数值；不能改变Graph、路径或执行选项。一次点击最多一次模型请求，不循环调模型。
3. 用户可手填候选，也可让AI建议。保存候选后，显示整批数值与输出位置；只有用户确认该批后才顺序运行。每个候选分别调用既有校验/启动/状态/结果/释放接口；不并发，不接管其他任务。
4. 执行前持久化starting状态，结果持久化后才能释放任务、开始下一个候选。停止/失败/保存失败/断连立即停止后续启动；未知状态不当作成功，不自动重试。
5. 每组使用独立WAV路径，保留参数、Graph基线、输入副本、实际状态与结果。重启加载记录时，未确认结束的任务标为中断；不自动恢复执行。记录损坏时明确报错，不猜测修复。
6. 对成功候选记录“更符合需求/可接受/不符合”和文字评价，允许复制路径到外部播放器试听。AI下一次建议能读取已保存的候选与人工评价；不发送音频样本，不声称听过音频。
7. 可把选中候选的参数恢复为编辑器草稿，使用新的输出路径；不自动执行、不覆盖已有结果。

## 接口与职责

- Rust桌面命令：`experiment_create(sessionId,spec)`、`experiment_list(sessionId)`、`experiment_load(sessionId,id)`、`experiment_save(sessionId,record)`；文件目标由软件生成，不接受模型指定的存储路径。记录与输入副本留在对应工作区，可跨应用重启读取。
- AI命令：`ai_experiment_candidates(sessionId,requestId,config,record)`，模型只可返回`propose_parameter_candidates`工具。候选必须通过本地数值与数量校验，执行还须逐图校验。
- React实验控制器：使用应用唯一音频会话，管理整批确认、串行运行与停止；切页不结束控制器。实验运行期间阻止普通任务启动/释放和工作区切换。
- C++：沿用现有Graph校验、文件权限、拒绝覆盖、状态与协作取消，不引入实验专属节点判断。

创建、提案、执行、评价分别为明确操作；参数搜索算法、跨Graph分支循环、实时实验、自动评价、内置音频播放和无人值守恢复不在本次范围。实验JSON不能包含API Key；真实模型请求仅由用户在界面主动发起，本轮开发仅使用本地测试。

## 实现边界

输入副本有独立SHA256校验文件，读写实验记录时检查内容；这用于发现外部修改，不是防恶意本机程序的OS沙箱。每个实验最多20批。记录不跨工作区搬移恢复，也不支持多个桌面实例同时操作同一实验。失败可能保留部分输出；停止后或保存失败时保留任务记录供检查，不自动删除文件。损坏记录会明确报错，原文件不会被覆盖修复。

模型在本实验入口中只看到`propose_parameter_candidates`工具，不能直接操作文件或启动批次；此前的`propose_audio_graph`仍用于工作台生成Graph。系统会主动把已保存的候选、数值指标和人工评价放入下次请求，这不是通用Agent自主工具循环。MCP接口本轮不变。

## 手动验收路径

1. 打开一个有PCM16 WAV的工作区，在Graph编辑器载入“音量调整”，设置真实输入文件路径，选择整段离线模式。
2. 打开“参数对比”，填写目标，勾选`gain.gain_db`，例如范围-12～0，点击“创建实验并复制输入”。应生成实验记录与输入副本，尚无候选输出。
3. 不用API先测手动候选：输入`[[-12],[-6],[0]]`并保存。确认整批后，应该依次出现三份独立输出，记录每组参数和结果。
4. 复制输出路径，在外部播放器试听，保存评价与备注。重启应用并打开同一工作区，从实验记录选择原实验，结果和评价仍在；不会重新执行。
5. 点击“AI建议下一批参数”，它只返回范围内候选。检查并保存后，仍须单独确认运行；AI调用需你自行使用已保存的模型配置，开发测试不消耗实际API余额。
6. 选成功结果“恢复到编辑器”，取消确认应不改变草稿；确认后参数符合所选候选，输出路径换新，且没有自动执行。
7. 用较长音频测试停止。停止后不应开始后续候选；关闭重启时，未明确结束的记录显示中断。批次不能再次原地执行，可另建一批。

前端自动测试覆盖不可变记录、数值边界、执行与保存顺序、提交中停止、保存失败取消及过期React状态；Rust测试覆盖持久化、快照校验、候选工具解析和真实control-cli文件处理。真实窗口交互、试听和模型供应商响应质量仍需上述手动验收。

## 本轮验证记录（2026-09-29）

- 前端72项测试通过，Rust40项通过、1项付费真实API测试忽略。
- 实际control-cli集成验证创建实验、固定输入、处理输出、保存/重读结果与拒绝被篡改的输入副本。
- 前端生产构建及Tauri调试EXE构建成功；独立子代理审核完成。未操作真实窗口或调用付费模型服务。
- 新增直接依赖为本机已缓存的sha2（输入副本校验）；没有新增npm依赖。现有工具链缺少rustfmt，未安装新工具，Rust自动格式化未执行。
- 本轮未提交仓库。

兼容性修正：用户报告同一配置下Graph生成成功、实验请求HTTP400。检查发现实验入口采用强制指定工具的`tool_choice`对象，而Graph入口为`auto`；实验现统一为`auto`，避免强制工具选择的兼容性差异。返回仍必须恰好包含合法候选工具及有界参数，否则不保存或执行。不自动重试、不改变用户模型配置；真实服务是否由此恢复仍需用户重试确认，不能仅凭HTTP400断言唯一原因。

修正验证：独立编写的本机HTTP模拟服务拒绝强制指定工具、接受实际`auto`请求，并确认候选校验仍有效。Rust41项通过、1项付费测试忽略，桌面重新构建成功；未调用真实供应商API。
